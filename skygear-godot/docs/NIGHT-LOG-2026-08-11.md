## 0 · THE REPOSITORY WAS BROKEN, AND IT IS REPAIRED

**Nothing committed was lost.** Read this section before distrusting any figure
below it, because for part of today no git command worked at all.

The machine freeze recorded in `NEEDS_ALEX.md` — the one that killed the AB-04
critic pass mid-run — zero-filled three files in `.git/`:

| File | State found |
|------|-------------|
| `.git/refs/heads/main` | 41 bytes, every one `\0` — branch pointer destroyed |
| `.git/index` | 169388 bytes, `bad signature 0x00000000` |
| `.git/logs/refs/heads/main` | final record NUL-padded to the end of the file |

Symptoms were `fatal: index file corrupt`, `error: invalid HEAD`, and
`badRefContent: refs/heads/main: invalid sha1 pointer 0000000000000000...`.
This is the ordinary NTFS signature of a hard stop with writes still pending,
not corruption of the object database.

**Diagnosis before action.** The reflog survived far enough to name the last
good commit, `6c96e7f` (*Ship ten demo-readiness fixes and an application
icon*), which matches build 70 in `NEEDS_ALEX.md`. Every object reachable from
it was then verified present:

```
git rev-list --objects 6c96e7f | wc -l          -> 5466
... | awk '{print $1}' | git cat-file --batch-check | grep -v 'commit|tree|blob|tag'
                                                -> empty (all 5466 intact)
```

**Repair, with the owner's approval, touching no file in the working tree:**

```
rm .git/refs/heads/main            # git refuses to update an unreadable ref
git update-ref refs/heads/main 6c96e7f
rm .git/index
git reset                          # mixed — rebuilds the index from HEAD
```

`git fsck` now reports only dangling objects, which are normal.
`git diff --check` is clean. All five pre-existing working-tree paths
(`NEEDS_ALEX.md`, `docs/BOARD.md`, `.codex-work/`, and the two untracked docs)
were left exactly as found. The only thing genuinely lost is *which files were
staged*, which the zeroed index had already destroyed.

**The lesson, which is worth more than the repair:** concurrent critic passes
with windowed Godot tooling can take this machine down, and when it goes down
mid-write it takes the git metadata with it. Critics are now run **serially**,
never two at once, and never two visual passes together.

*"The cleave indicator is correct, but the vfx is triggering behind the player?"*

**The first clause retired AB-04's kill condition on his own eyes.** The second

The angle math was clean and was instrumented to prove it: simulation cone
−102.00°, effect-stamped direction −102.00°, **stamp − sim = 0.00°** on both
beats, `side` latched correctly, `cleave_lead` a transient ±31.5° decaying to
zero over the swing's 0.16 s life. The fault was the painted plate. Measured
twice independently from `assets/art/fx/slash_arc.png` (384×256):

```
front (+X half)                    16.9%
back  (-X half)                    83.1%
within ±30 deg of +X (the aim)      0.0%   <- the two bins straddling the
alpha centroid            162.4 deg off aim    aim axis are exactly empty
```

The decal aims its quad's +X at the target correctly and then paints a crescent
that lives 162° away, so the captain swings north and the picture appears south.
Not draw-order: the decal cull mask excludes `LAYER_FIGURES`, so it never
renders under her model.

**Pre-existing, with git evidence.** `git show c27ca88:…view3d.gd` carries the
identical `_art("slash", …)` draw at line 5088 — before AB-04 — and
`slash_arc.png` last changed in `151ec7f` ("v12"). AB-04 is innocent; what it
did was put a *correct* mark beside a wrong one every beat, which is why the
disagreement finally became visible.

Owner's verdict: **generated now, repaint later.** One expression in
`view3d.gd:5209`, with the measured numbers and SG-63's precedent written in
place, because retiring a hand-painted plate is an **evidenced exception** to
`view3d.gd:3732`'s "painted beats generated" doctrine, not a preference. New
check reads the RESOLVED texture off the production path:

```
old wrap restored:  FAIL … 0.0% of resolved-texture alpha within ±30° of +X
                          against a floor of 25%          1203/1204
fix restored:       ok   … 62.0% …                        1204/1204
```

**Still unconfirmed:** the generated fan is a RIM where the plate was a solid
crescent, so the deck mark may now read thinner. Rotating the old plate is NOT
an alternative — its band spans ~±150°, wider than the 140° cone, so even
