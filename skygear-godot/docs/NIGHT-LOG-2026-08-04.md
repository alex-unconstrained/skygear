## The rig fault this pair found, and it is SG-190 one frame deeper

SG-190 established that a hand-stepping rig must be inside a physics frame or
`move_and_slide()` integrates the idle wall clock. What it did not establish is
that being inside a physics frame is enough.

Measured in `tools/crew_probe.gd`, after `Engine.physics_ticks_per_second = 20`
and two `await physics_frame`s:

| | |
|---|---|
| `Engine.physics_ticks_per_second` | 20 |
| `Engine.is_in_physics_frame()` | true |
| `root.get_physics_process_delta_time()` | **0.01667** |
| what `move_and_slide` actually integrated | **0.05** |

The walk identity caught it: `ground / (|v| × DT)` came back **2.87**, and
0.05 / 0.01667 is 3.00. A rig that asks for a clock and is told it has one is not
a rig that has one.

`crew_probe` sets no tick rate at all — it takes the rate the engine is already
running at, steps at exactly that, and proves the identity above every result.
Three times as many steps per run, and worth it.

The same identity was added to `melee_probe`, where it reads **1.00** in every
arm the subject actually walks in — so that rig's 0.05 step is sound and its
numbers stand. It reads 0.33 when the subject is pressed against the captain's
collider, which is `move_and_slide` sliding along a body and not a clock fault at
all; the sample is restricted to frames with room to walk for exactly that
reason. That near-miss is worth remembering: **0.33 is what a real clock fault
looks like, and it is also what standing next to something looks like.**

## SG-198 / SG-199 — Muster stops on an ordering-contract conflict

SG-198 was built red-first. The ten exact `muster ·` names first produced
**1133/1143**, with only those ten new checks red. The pure planner, twelve-plan
cache, deep-copy reader, local RNG, four grammars, budget filter and feature-off
seam now parse. The ten substantive checks themselves are green: all four
forced grammars satisfy their postconditions, 288 plans keep valid types/lanes
and the final queue schema, 24 fixed seeds produce 12 distinct wave-6 plans,
flat collapses the same signature to one, cached/twin/on-demand plans match,
and planning leaves both live RNG states unchanged.

The full harness is nevertheless **1142/1143**, and the remaining red is not a
gameplay defect that can be tuned away:

`tempo · STEADY deals today's queue byte-identically`

Design §16.2 requires two incompatible things. The flat seam must reproduce the
authored queue byte-for-byte, and final plans must sort by time, source, lane
and member. HEAD's queue builder sorted by time alone. Equal-time entries
therefore have a deterministic but non-lane-ordered tie pattern. Wave 3 proves
the conflict:

- legacy time-only sort, lane order at 0.00 / 0.22 / 0.44 / 0.66 seconds:
  `012 / 021 / 210 / 102`;
- required stable sort at those same times: `012 / 012 / 012 / 012`.

The entries, types and times are identical; only equal-time array order differs.
No assignment of the real lane field can make a time/source/lane/member sort
produce the old permutation. Weakening the legacy control would make the
required byte-identity check incapable of firing, while silently using the old
sort everywhere would violate the fixed build order.

SG-199 therefore stops SG-198 before G3 or merge. Coordinator recommendation:
make the rollback seam explicit — `SKYGEAR_MUSTER_FLAT` alone uses the legacy
time-only sort, while live Muster uses the new stable order. The alternative is
to adopt stable ordering under flat and explicitly waive byte identity. The
decision is item 1 in `/NEEDS_ALEX.md`. Implementation remains unmerged.
